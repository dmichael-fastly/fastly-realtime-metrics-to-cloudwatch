# Fastly Real-Time Metrics to CloudWatch

See `README.md` for architecture (serverless polling loop: EventBridge → Lambda → Fastly Real-Time API → CloudWatch), configuration, cost analysis, and getting-started docs.

## Commands
- `.venv/bin/pytest src/test_lambda_function.py` — run tests. Python 3.12 venv at `.venv/`; `pytest.ini` sets `pythonpath` and asyncio auto mode, so run from the repo root.
- `python3 scripts/export_config.py` — regenerate `terraform/metrics_config.json` after editing `metrics.ini` (required before terraform commands; `deploy.sh` does it automatically).
- `terraform fmt -recursive` and `terraform validate` — run from `terraform/`.
- `./deploy.sh` (or `-y` to auto-approve) — zips `src/` + `metrics.ini` and runs `terraform apply` against real AWS. High-impact: requires explicit human approval every time.
- `./teardown.sh` — destroys all AWS resources. Never run without explicit approval.

## Key files
- `src/metrics_config.py` — **single source of truth** for metric naming (`to_cloudwatch_name`), units, and `metrics.ini` parsing. Both the Lambda and the Terraform export consume it.
- `src/lambda_function.py` — polling loop, `aiohttp` fetches, sparse-data parsing, `PutMetricData` batching.
- `scripts/export_config.py` — generates `terraform/metrics_config.json` (gitignored) from `metrics.ini`; run automatically by `deploy.sh`, run manually before `terraform plan`/`validate` outside a deploy.
- `src/test_lambda_function.py` — pytest suite covering parsing, flattening, sparse data, cold starts, and a guard that Terraform only references metric ids known to `metrics.ini.example`.
- `metrics.ini` — manifest of which Fastly metrics get pushed (controls CloudWatch storage cost). Untracked; `metrics.ini.example` is the shipped template.
- `terraform/dashboard.tf` / `terraform/origin_dashboard.tf` — data-driven dashboards: widget definitions list Fastly metric ids, and names come from `metrics_config.json` lookups. Widgets render only the ids actually tracked.
- `terraform/alarms.tf` — per-service alarms: 5xx spikes, zero traffic, high latency. Metric names are lookups too; alarms are skipped when their ids aren't tracked.

## Conventions and gotchas
- **Sparse data model**: Fastly's real-time API omits a metric key entirely when its value is zero in that 1-second bucket. All parsing must treat a missing key as 0, never as an error.
- **Never hardcode a CloudWatch metric name in Terraform** — reference `local.edge_metrics["<fastly_id>"]` / `local.origin_metrics[...]` so names always come from the generated config. A hardcoded name is the drift bug this architecture exists to prevent.
- **CloudWatch namespaces**: `Fastly/RealTime` (edge) and `Fastly/OriginInspector` (origin).
- **Secrets**: the Fastly API token lives in `terraform/terraform.tfvars` (gitignored) and AWS Secrets Manager at runtime. Never hardcode, log, or commit tokens.
- **Build artifacts**: `package/` and `lambda.zip` are generated by `deploy.sh` — never edit them by hand.
